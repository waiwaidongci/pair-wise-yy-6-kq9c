# 墨锭试磨室

运行：

```bash
npm start
```

访问 `http://localhost:3037`。数据保存在 `data/ink-stick-testing.json`。

续磨规则自测：

```bash
npm test
```

## 页面分页

- **旧试磨记录**：墨锭建档、状态、备注与试磨评分，维持原有行为，可单独查看。
- **续磨链**：按砚台记录每一段研墨。

## 续磨链规则

每段记录 **砚台、研墨分钟、残墨量（克）、研磨人**，新的一段自动接在同砚未结算的最后一段后面；同砚同一时间只能挂一段（`active`）。

- 段状态：`active`（挂砚中）/ `chained`（已被后续段接上）/ `halted`（前段改正后被停用）/ `settled`（已结算，登记余墨去向）。
- 一条链累计研墨 **超过 40 分钟**，或末段残墨 **少于 2 克** 时，卡片与提交响应都会提示换砚（恰好 40 分钟 / 2 克不提示）。
- 结算末段时必须填写余墨去向，整条链随之收束；之后该砚台可以另开新链。
- 改正前段数据后，其所有后续段先置为停用，需按顺序逐段启用；停用段挡路时不能续磨。
- 只有链上第一段能更换砚台，且不能换到正挂着段的砚台。

## 结构（三类职责分开）

| 文件 | 职责 |
| --- | --- |
| `lib/store.js` | 记录存放：只管 JSON 的读写与初始数据 |
| `lib/chains.js` | 续磨判定：续接、结算、改正停用、逐段启用、累计与换砚提示（纯逻辑，不碰文件和页面） |
| `server.js` | 卡片/页面操作与 HTTP 路由，判定委托给 `chains.js`，存取委托给 `store.js` |

续磨链数据存放在数据文件的 `grindChains` 字段，与旧试磨 `items` 互不影响。

### 续磨链 HTTP 接口

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/chains` | 续磨链只读视图（含累计分钟、换砚警告、停用段数） |
| `POST /api/chains/segments` | 续磨一段（同砚自动接尾段，新砚开新链） |
| `PATCH /api/chains/segments/:id` | 改正某段数据，后续段停用 |
| `POST /api/chains/segments/:id/resume` | 按序启用停用段 |
| `POST /api/chains/segments/:id/settle` | 结算末段，提交 `{ "destination": "余墨去向" }` |
